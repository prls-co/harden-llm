# Query Analytics weather transport RCA

## 1. Reproduced cause

Query Analytics run `qar_33124d546ff8a7d79717f12504644590` stopped during
Visibility company extraction. The persisted NER request contains 5,722 UTF-8
bytes of source text, model `gpt-6-luna`, reasoning `low`. Harden admitted a
59,998ms generation budget but stopped at 30,001ms with `ETIMEDOUT`, no response
headers and no output. Permit `68f5be8d-bb5c-5885-84f9-f31a47781535` records the
60-second deadline and the earlier local stop. NER correctly returned an
unresolved outcome; Query Analytics subsequently corrected its generic failed
projection in PR #20.

Ordinary typed Responses requests omit an upstream streaming option. CPA then
buffers generation before sending headers; Harden's independent 30-second
response-header timer expires while the accepted logical deadline is still in
the future. Passing `harden.timeout_ms=60000` cannot change that transport timer.

## 2. Why NER passing did not cover this condition

NER's pinned source-quality corpus contains 35 cases, with source texts of
40–323 bytes; its active live campaign excludes the four user-deferred cases.
The normal `make verify` runs the live harness's deterministic request,
transport and stop tests, rather than `TestSourceQuality` itself. The separate
live corpus qualification and larger deterministic payload-limit tests do not
exercise a real CPA generation that finishes after the response-header budget.
The weather failure used NER's normal model/reasoning configuration but a much
longer generated answer. No prompt/schema/model/reasoning change is made here.

## 3. Correction and regression

CPA Responses payloads now select upstream streaming by default. The ordinary
client still receives a single buffered, validated JSON result; explicit stream
choices and other provider defaults remain unchanged. The logical generation
deadline, accounting, admission and unknown-outcome rules remain unchanged.

`TestOrdinaryCPAResponsesCompletesAfterHeaderBudgetWithoutIncreasingDeadline`
uses the actual typed HTTP client, gateway, stateful core and local TLS provider.
It scales the header/generation budgets down and completes after the header
budget but before the logical deadline. Before the correction it failed after
one dispatch; afterwards it succeeds with one dispatch and complete output.
The existing uncertainty-projection and provider-dispatch regressions also pass.

## 4. Separate interrupted stream

Reported run `qar_d48b4735c6a915f327ea653c897d7a65` lost a Solutions re-clustering
stream after 5.1 seconds, with partial output and no terminal provider response.
Harden history `c1803240-744c-4fc8-8621-072908a39fdc`, CPA correlation `dd85d417`.
Its logical deadline was still 60 seconds; this is distinct from the 30-second
header cutoff. The available trace records `NETWORK_ERROR` but not the original
socket error, so the failed network hop remains unproven. CPA's HTTP receipt
finished at 10.711 seconds, after Harden stopped reading. The bounded stream
and unconfirmed-dispatch rules must not be bypassed by a blind inference replay.

## 5. Acceptance

The deterministic reproduction and focused regressions pass. Broad checks,
immutable image deployment and a fresh full product weather run are recorded
when completed. Green NER or Harden unit tests alone do not close live weather
acceptance. Original failed runs and private raw evidence remain retained.
