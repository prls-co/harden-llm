# Issue 186 — gateway contract failures and remediation plan

## 1. Decision and production exposure

Treat [#186](https://github.com/prls-co/harden-llm/issues/186) as a routine correctness patch for the inspected production deployment. Start by rejecting an undeclared search selection and rejecting explicit caching with function tools. Either case can return misleading success. Keep the storage observation open as a native Responses compatibility gap. It does not justify a new cross-provider storage policy or changes to the batch worker.

`store: false` asks a Responses provider to disable storage of the generated response for later API retrieval. Inference still works. Harden's ordinary API has no stored-response retrieval workflow and rejects `store: true`. Provider abuse-monitoring logs, Harden's own cache and job artifacts have separate controls. Existing callers can continue sending false. Dropping the field from Model Recall would break the opt-out for destinations where omission enables storage. ## 3. Where each contract breaks

### 3.1 Storage opt-out disappears during request preparation

Both wire structs use `*bool`, so the decoder knows the difference between omission and false. The statelessness check rejects true. Each public handler then constructs a fresh provider-options map and leaves out `Store`. On the native Responses route the payload builder emits what it was given. The value was already lost in the gateway. The October proxy change introduced the request path. The Model Recall regression sends false but asserts the result text, schema error, and dispatch count. It never inspects this upstream field. [Wire types and storage validation](../internal/gateway/httpapi/requests.go) · [Request preparation](../internal/gateway/httpapi/handlers.go) · [Model Recall regression](../internal/gateway/httpapi/structured_output_test.go) · [October change](https://github.com/prls-co/harden-llm/commit/009051c)

Adding a map entry in the handler would fix the simplest reproduction. Two code paths make that insufficient. Model-target repair or rerun intentionally replaces the generation's provider options. Also, the Anthropic payload builder copies generic options, and some connections classified as `responses` actually send to Perplexity's `/agent`. Any future claim about opt-out forwarding must be checked at the actual upstream endpoint, including when recovery selects a different model. The router hashes the prepared operation payload, so emitting false there also keeps an explicit native opt-out from hitting an older entry produced with the field absent. [Recovery target selection](../internal/runtime/recovery_execute.go) · [Protocol and endpoint selection](../internal/providers/payload.go) · [Prepared cache identity](../internal/providers/router.go)

### 3.2 Search selection loses its tool type before validation

`decodeTools` already separates the search declaration from the function list. Since `d67c026`, `decodeToolChoice` has converted a recognized search object directly to the generic mode `required`. It never receives the decoded declaration. The core correctly accepts `required` with a declared function. By then it cannot tell which tool the caller selected. The existing parity test covers matching search declarations and intentionally accepts a preview selector with a standard search declaration. That alias behavior is part of the regression contract. [Decoder](../internal/gateway/httpapi/requests.go) · [Core validator](../tools.go) · [Existing alias and choice tests](../internal/gateway/httpapi/web_search_request_test.go) · [November change](https://github.com/prls-co/harden-llm/commit/d67c026)

### 3.3 Cached output loses its Go type

The provider normalizer returns `AssistantOutput` with typed tool calls. On a miss or refresh, the renderer can extract those calls. The cache serializes `Output any` into JSON and decodes it back into an untyped map. The integrity checks succeed because the record has valid JSON, version and identity. The shared renderer treats ordinary maps as structured output and serializes them as text. Responses consequently emits a message, and Chat emits no tool calls and chooses `finish_reason="stop"`. The hit reached neither search nor the model. SDK and cache tests previously exercised these paths independently. [Provider normalization](../internal/providers/normalize.go) · [Cache codec](../client_cache.go) · [Both renderers](../internal/gateway/httpapi/responses.go) · [SDK contract](../internal/gateway/httpapi/openai_contract_test.go)

The codec also serves direct Go clients. A public HTTP admission rule resolves the issue's requested contract at both routes. Supporting typed function replay for Go consumers would require a separately specified cache format and handling for existing records. Inferring a function from a map with a `tool_calls` key would misclassify legitimate structured JSON. [Cache contract and replay tests](../client_cache_test.go)

## 4. Implementation order and acceptance

1. **Search.** Validate a recognized object selector against the already-decoded search declaration in request preparation, before converting it to `required`. Use the existing search-type predicate and error writer. Cover all four accepted aliases with function-only and empty tool lists. Expect HTTP 400 with `error.param="tool_choice"` and zero model/search calls. Keep the cross-alias positive case, the ordinary function-only string `"required"`, named functions, and the existing mixed-declaration error. A malformed batch item reaches the same preparation path and must fail before submission. The batch endpoint's existing prohibition on search execution still applies.
2. **Cache.** Add one shared public-handler check after tool decoding and cache-mode parsing, before tracking or execution. Any declared function plus `cache` or `refresh` returns HTTP 400 with `error.param="harden.cache"`, including `tool_choice="none"`. Count zero reads, writes, and provider calls, including a pre-existing record and a request with `stream: true`. Assert an ordinary JSON error before SSE headers. Run positive controls for both routes and both allowed modes using the official SDK. Check call ID, name, arguments, Responses item type and Chat finish reason. Keep text, structured object and search-only cache hit/refresh controls, including a structured object containing a field named `tool_calls`. Existing records can expire normally. [Cache defaults](../internal/gateway/httpapi/requests.go) · [Cached search decision](../docs/adr/ADR-HLLM-019-cached-web-search-routing.md)
3. **Contract and verification.** Update both public request schemas and the route descriptions in `api/openapi.yaml`, plus the examples and compatibility note in `docs/api-and-library.md`. Document the migration to omitted cache mode or `off` for tool callers. Exercise schema validation and handler behavior with the same valid and invalid fixtures. Extend the existing canonical cases for SDK behavior (`TEST-403`), search choice (`TEST-535`), cache behavior (`TEST-008/011`) and shared job admission (`TEST-475`). Record the changed oracles in the test catalog. Run focused Go tests first, then `make test-fast` with the pinned toolchain. No live upstream is needed to inspect an emitted JSON member or count a dispatch. [OpenAPI](../api/openapi.yaml) · [Caller documentation](../docs/api-and-library.md) · [Test catalog](from_utility-llm/harden-llm-self-hosted-test-spec.md)

### 4.1 Storage and batch disposition

Keep the opt-out on direct OpenAI callers. The production default already applies it downstream on the CPA Codex route. Record the limitation for native Responses connections that forward what Harden sends. Revisit forwarding before enabling a direct OpenAI route in production, if a self-hosted caller needs that guarantee, or if a customer or internal obligation is identified. Prefer a fixed upstream setting for that connection if the operating requirement is that every call disable response storage. Verify the final wire body for generation and recovery before advertising that guarantee. The current evidence supports deferring a new root request property, provider capability registry, or universal rejection rule.

Leave `/v1/jobs` as it is. It uses the fixed CPA target and already requires caching off. The shared validation of an undeclared search selector is sufficient. Changing the worker default or adding a persisted property would provide no demonstrated benefit on the inspected Codex route. Adding the property could also turn a retry of an accepted job into an idempotency conflict. [Batch request preparation](../internal/gateway/httpapi/jobs.go) · [Database comparison](../stateful/batch/store.go)

## 5. Release criteria

The two validation changes are ready for dev when their new tests fail for the expected reason on the baseline and pass on the candidate, with the existing fast suite green. Record the candidate SHA and fixture results. For an authorized deployment, record the gateway image and verify health/auth and an authenticated invalid request returning the expected 400 before dispatch. Report the native Responses storage item separately as deferred while its acceptance checkbox is open. The two closed evaluations retain their own demand criteria.
